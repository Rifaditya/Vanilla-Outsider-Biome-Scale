## 🎮 Step-by-Step Player Workflow & Snapshot Behavior

In **Minecraft 26.3**, the chunk generator calls `MultiNoiseBiomeSource` during terrain building passes:

```
[ Chunk Generation Triggered (26.3 Snapshot Engine) ]
                          │
                          ▼
[ Sampler Requests Biome at (X, Y, Z) ]
                          │
                          ▼
[ Biome Scale Mixin Intercepts X & Z ]
                          │
                          ├── Read cachedScaleModifier from Server Tick
                          └── Transform: X' = (int)(X / S), Z' = (int)(Z / S)
                          │
                          ▼
[ Vanilla Noise Sampler Evaluates 6D Climate Parameters at (X', Y, Z') ]
                          │
                          ▼
[ Biome Holder Returned & Painted into Chunk Sections ]
```

1. **Chunk Generation**:
   - The world generator samples coordinates for temperature, humidity, continentalness, erosion, depth, and weirdness.
2. **Instant Coordinate Dilation**:
   - As coordinates enter the biome sampler, the X and Z coordinates are divided by the active scale modifier.
   - Points that were originally 2,000 blocks apart are evaluated as if they were only 1,000 blocks apart (under $2.0\times$ scaling), resulting in biomes expanding across twice the physical distance.
3. **Exploration Experience**:
   - Players traverse vast, expansive deserts, sprawling continuous mountain ranges, and monumental oceans rather than encountering rapid patchwork micro-biomes every few hundred blocks.
4. **Dynamic Mid-Game Changes**:
   - Adjusting `/gamerule biome_scale:scale_modifier` mid-game affects **only newly generated chunks**. Already generated chunks remain completely intact.

## 📐 Mathematical Formulation & Voronoi Geometry

### 1. GameRule Scaling Multiplier Formula

The integer value stored in `biome_scale:scale_modifier` represents a percentage scale factor $S$:

$$S = \frac{V_{\text{gamerule}}}{100.0}$$

Where:
* $V_{\text{gamerule}} = 200 \implies S = 2.0$ ($2.0\times$ vanilla diameter)
* $V_{\text{gamerule}} = 400 \implies S = 4.0$ ($4.0\times$ continental scale)
* $V_{\text{gamerule}} = 50 \implies S = 0.5$ ($0.5\times$ micro-biome scale)

To prevent division by zero or negative coordinate inversion, a protective lower bound is enforced:

$$S_{\text{eff}} = \max(S, 0.01)$$

### 2. Coordinate Transformation Equations

The coordinate inputs $(x, y, z)$ entering `MultiNoiseBiomeSource.getNoiseBiome` are mapped to dilated sampling coordinates $(x', y', z')$:

$$x' = \begin{cases} x & \text{if } S_{\text{eff}} \le 0.01 \\ \left\lfloor \frac{x}{S_h} \right\rfloor & \text{otherwise} \end{cases}$$

$$z' = \begin{cases} z & \text{if } S_{\text{eff}} \le 0.01 \\ \left\lfloor \frac{z}{S_h} \right\rfloor & \text{otherwise} \end{cases}$$

$$y' = \begin{cases} y & \text{if } S_v \le 0.01 \\ \left\lfloor \frac{y}{S_v} \right\rfloor & \text{otherwise} \end{cases}$$

*(In the active MC 26.3 implementation, $S_h = S_{\text{eff}}$ and $S_v = 1.0$, preserving vertical 3D cave and mountain climate bands while dilating horizontal expanse).*

### 3. Voronoi Cell & Climate Vector Preservation

Minecraft evaluates biomes by finding the minimum Euclidean distance in the 6D climate space between the sampled climate vector $C(x', y', z')$ and pre-registered biome target points $B_k$:

$$C(x', y', z') = \big\langle T(x',y',z'),\, H(x',y',z'),\, C_{\text{cont}}(x',y',z'),\, E(x',y',z'),\, D(x',y',z'),\, W(x',y',z') \big\rangle$$

$$\text{Selected Biome} = \arg\min_{k} \left\| C(x', y', z') - B_k \right\|_2$$

Because the coordinate transformation $(x, z) \mapsto (x/S, z/S)$ is continuous and monotonic:
* **Cell Topology is Preserved**: Voronoi boundaries retain their organic curved contours without sharp discontinuities or shearing.
* **Octave Gradient Dilated**: Noise gradient $\nabla N(x', z')$ scales by $\frac{1}{S}$, creating smooth, sweeping climate transitions.

```
       [ VANILLA 26.3 (S = 1.0) ]                 [ SCALED 26.3 (S = 2.0) ]
       
   (X=0)              (X=1000)             (X=0)                                (X=2000)
     +--------------------+                  +------------------------------------+
     | PLAINS   | DESERT  |                  |               PLAINS               |
     | [500 blk]| [500 blk|                  |             [1000 blk]             |
     +--------------------+                  +------------------------------------+
```

## 💻 Developer & Mixin Implementation Hooks

The core transformation is executed in [`MultiNoiseBiomeSourceMixin`](file:///Biome%20Scale%20v26.3/Biome%20Scale%2026.3/src/main/java/net/vanillaoutsider/biomescale/mixin/MultiNoiseBiomeSourceMixin.java):

```java
@Mixin(MultiNoiseBiomeSource.class)
public class MultiNoiseBiomeSourceMixin {

    @ModifyVariable(
        method = "getNoiseBiome(IIILnet/minecraft/world/level/biome/Climate$Sampler;)Lnet/minecraft/core/Holder;",
        at = @At("HEAD"),
        argsOnly = true,
        ordinal = 0
    )
    private int biomescale$modifyX(int x) {
        double scale = BiomeScaleRules.cachedScaleModifier;
        if (scale <= 0.01) return x;
        return (int) (x / scale);
    }

    @ModifyVariable(
        method = "getNoiseBiome(IIILnet/minecraft/world/level/biome/Climate$Sampler;)Lnet/minecraft/core/Holder;",
        at = @At("HEAD"),
        argsOnly = true,
        ordinal = 2
    )
    private int biomescale$modifyZ(int z) {
        double scale = BiomeScaleRules.cachedScaleModifier;
        if (scale <= 0.01) return z;
        return (int) (z / scale);
    }
}
```

### Zero-Allocation Performance Analysis
* **Stack Primitives**: Variables `x` and `z` are modified as primitive `int` values directly on the JVM operand stack.
* **No Object Instantiation**: Zero `new` statements, zero boxing/unboxing (`java.lang.Integer`), and zero lambda closures are executed in the hot sampling loop.
* **Thread Independence**: Reads `cachedScaleModifier` (a primitive `double` field updated once per server tick on the main thread), ensuring lock-free read access across parallel snapshot worker threads.
