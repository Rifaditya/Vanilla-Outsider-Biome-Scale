## 🎮 Step-by-Step Administrator Workflow

Managing worldgen biome scaling is entirely integrated into Minecraft's native `/gamerule` command suite:

```
[ Administrator issues /gamerule ]
               │
               ▼
[ Minecraft Server updates GameRule in LevelData ]
               │
               ▼
[ ServerTickEvents.START_SERVER_TICK fires (50ms interval) ]
               │
               ▼
[ BiomeScaleRules.getScaleModifier reads Level ]
               │
               ▼
[ BiomeScaleRules.cachedScaleModifier updated ]
               │
               ▼
[ All subsequent chunk generation queries use new modifier ]
```

### 1. Inspecting the Current Scale Modifier
To query the active biome scale multiplier in chat or server console:
```text
/gamerule biome_scale:scale_modifier
```
*Expected response:*
```text
Gamerule biome_scale:scale_modifier is currently set to: 200
```

### 2. Changing the Biome Scale Multiplier
To update the scale factor for all future chunk generation:
```text
/gamerule biome_scale:scale_modifier <integer_value>
```

**Common Examples:**
* Double size ($2.0\times$, default):
  ```text
  /gamerule biome_scale:scale_modifier 200
  ```
* Triple size ($3.0\times$):
  ```text
  /gamerule biome_scale:scale_modifier 300
  ```
* Quadruple continental size ($4.0\times$):
  ```text
  /gamerule biome_scale:scale_modifier 400
  ```
* Vanilla 1:1 parity ($1.0\times$):
  ```text
  /gamerule biome_scale:scale_modifier 100
  ```
* Micro-biomes ($0.5\times$):
  ```text
  /gamerule biome_scale:scale_modifier 50
  ```

## 📐 Mathematical Cache Model & Tick Timing

The mod avoids query overhead during chunk generation by pre-evaluating the modifier once per server tick on the overworld dimension:

$$T_{\text{tick}} = 50\,\text{ms} \quad (20\,\text{ticks} = 1.0\,\text{s})$$

$$\text{cachedScaleModifier} = \begin{cases} 0.01 & \text{if } V \le 0 \\ \frac{V}{100.0} & \text{otherwise} \end{cases}$$

Where $V$ is the raw integer fetched from `DynamicGameRuleManager.getInt(level, GLOBAL_BIOME_SCALE_MODIFIER)`.

Because Minecraft chunk generation workers sample biomes millions of times when populating terrain noise, reading from the precomputed primitive `cachedScaleModifier` reduces lookup latency to **sub-nanosecond** speeds.

## 💻 Developer & API Extension Hooks

The GameRule is registered through `DasikLibrary` in [`BiomeScaleRules.java`](file:///Biome%20Scale%2026.1/src/main/java/net/vanillaoutsider/biomescale/BiomeScaleRules.java):

```java
public class BiomeScaleRules {
    public static final GameRuleCategory CATEGORY = DynamicGameRuleManager.registerCategory(
            Identifier.fromNamespaceAndPath("biome_scale", "biome_scale")
    );

    public static GameRule<Integer> GLOBAL_BIOME_SCALE_MODIFIER;
    
    public static double cachedScaleModifier = 2.0;

    public static double getScaleModifier(Level level) {
        if (GLOBAL_BIOME_SCALE_MODIFIER == null) return 2.0;
        int val = DynamicGameRuleManager.getInt(level, GLOBAL_BIOME_SCALE_MODIFIER);
        if (val <= 0) return 0.01; // prevent zero division logic later
        return val / 100.0;
    }

    public static void init() {
        GLOBAL_BIOME_SCALE_MODIFIER = DynamicGameRuleManager.integerRule("biome_scale:scale_modifier", CATEGORY, 200)
            .register();

        ServerTickEvents.START_SERVER_TICK.register(server -> {
            cachedScaleModifier = getScaleModifier(server.overworld());
        });
    }
}
```

### Integration for External Mods
External Fabric mods or addons can read the active scale factor at runtime without reflection:
```java
// Query active scale modifier directly from BiomeScaleRules
double currentScale = net.vanillaoutsider.biomescale.BiomeScaleRules.cachedScaleModifier;
```
